# 快速开始

同文运行在本机，浏览器界面与后端使用同一个地址。仓库提供源码、已构建界面和合成资料，正常启动不需要重新构建前端。

## 安装与启动

安装 Node.js 24，在仓库目录执行：

```powershell
npm install --omit=dev --ignore-scripts
npm start
```

打开 <http://127.0.0.1:3010/>。首次启动建立六份合成文档；后续保留自己的修改、版本和运行记录。

## 配置模型

需要使用真实检查时，将 `.env.example` 复制为 `.env`：

```powershell
Copy-Item .env.example .env
```

在 `.env` 中自行填写模型 API key，然后重新启动。其余接口配置按示例与现有适配保持一致。密钥由后端读取，数据库保存在本机 `runtime/`；两者都被 Git 忽略。

没有 key 时仍可浏览、编辑、保存及查看版本。模型检查需要配置完成后才能运行。

## 确认与关闭窗口

检查结果中，勾选可确认的建议，再点击“确认修改”。部分确认后窗口保留；全部处理完且没有剩余事项时自动关闭。

- 右上角×：关闭窗口和底部停靠条，检查记录保留。
- 底部“收起”：折叠为停靠条，便于继续处理。
- 工具栏“修订记录”：重新打开结果，查看保存批次或撤销。
- “停止本次检查”：结束正在进行的检查；关闭窗口本身只改变显示。

## 常见启动问题

| 情况 | 处理 |
| --- | --- |
| Node 版本不符合 | 使用 Node.js 24 后重新启动 |
| 地址无法访问 | 确认终端中的服务仍在运行，并按终端显示的端口打开 |
| 端口被占用 | 在 `.env` 中调整 `PORT`，重启后使用新地址 |
| 只能编辑、不能检查 | 核对 `.env` 的模型 API key 与接口配置，重启服务 |
| 旧建议不可确认 | 资料、范围或执行版本已变化；重新检查当前资料 |

## 重建界面

需要修改前端时，将 `package.source.json` 另存为 `package.json`，安装开发依赖后构建：

```powershell
Copy-Item package.source.json package.json
npm install --ignore-scripts
npm run build:ui
```
